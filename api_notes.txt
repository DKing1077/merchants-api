MERCHANTS API - STUDY NOTES
===========================

─────────────────────────────────────────
1. DATABASE  (app/db/database.py)
─────────────────────────────────────────
engine        = create_engine(settings.database_url)
               connects SQLAlchemy to Postgres

SessionLocal  = sessionmaker(autocommit=False, autoflush=False, bind=engine)
               factory that produces DB sessions

Base          = declarative_base()
               all models inherit from this

get_db()      generator used as a FastAPI dependency (Depends)
               yields a session, closes it in finally block

create_database_if_missing()
               connects to postgres admin db, checks pg_database,
               creates target db if absent


─────────────────────────────────────────
2. MODELS  (app/db/models/models.py)
─────────────────────────────────────────
All models inherit Base and map to a Postgres table.

PaymentIntent  table: payment_intents
  id               String PK  (e.g. "pi_1")
  merchant_id      String indexed
  amount           Integer (in cents)
  currency         String(3) e.g. "GBP"
  status           String  (requires_payment_method → requires_capture → succeeded / canceled)
  idempotency_key  String unique nullable
  is_flagged       Boolean default False
  review_status    String nullable  (pending_review / approved / rejected)
  review_reason    Text nullable
  created_at / updated_at  DateTime auto

Refunds  table: refunds
  id                String PK (uuid)
  merchant_id       String indexed
  payment_intent_id String FK → payment_intents.id
  amount            Integer
  status            String  (pending → confirmed / declined / canceled)
  idempotency_key   String unique nullable
  is_flagged / review_status / review_reason  same pattern as PaymentIntent

Event  table: events
  id          String PK (uuid)
  type        String indexed  e.g. "payment_intent.created"
  object_id   String indexed  (the PI or refund id)
  payload     JSONB
  created_at  DateTime

WebhookEndpoint  table: webhook_endpoints
  id           String PK (uuid)
  merchant_id  String indexed
  url          Text
  event_types  JSONB  (list of event type strings)
  secret       String  (hex token for HMAC signing)
  is_active    Boolean default True

WebhookDispatch  table: webhook_dispatches
  id                   String PK (uuid)
  event_id             String FK → events.id
  webhook_endpoint_id  String FK → webhook_endpoints.id
  payload              JSONB
  status               String  (pending / success / failed)

WebhookDelivery  table: webhook_deliveries
  id                   String PK (uuid)
  webhook_dispatch_id  String FK → webhook_dispatches.id
  attempt_number       Integer default 1
  response_status      Integer nullable
  response_body        Text nullable
  error_message        Text nullable
  status               String  (pending / success / failed)
  next_retry_at        DateTime nullable
  delivered_at         DateTime nullable

LedgerAccount  table: ledger_accounts
  id            String PK (uuid)
  merchant_id   String indexed
  name          String
  account_type  String  (e.g. "cash", "merchant_payable")
  currency      String(3)

LedgerEntry  table: ledger_entries
  id              String PK (uuid)
  entry_type      String  (e.g. "payment_succeeded", "refund_confirmed")
  reference_id    String nullable indexed  (links to PI or refund id)
  description     Text nullable
  entry_metadata  JSONB nullable

LedgerPosting  table: ledger_postings
  id          String PK (uuid)
  entry_id    String FK → ledger_entries.id
  account_id  String FK → ledger_accounts.id
  amount      Integer  (positive = debit, negative = credit)
  currency    String(3)
  NOTE: postings in one entry must sum to zero (double-entry bookkeeping)

─────────────────────────────────────────

    /v1/refunds          → refunds.router

All routes use Depends(get_db) to inject a DB session.
Errors from the service layer are caught and re-raised as HTTPException.

                                reads Idempotency-Key header
GET  /admin/flagged             list flagged payment intents
GET  /transactions              all transactions across all PIs
GET  /{id}/transactions         transactions for one PI
GET  /{id}                      get single payment intent
POST /{id}/flag                 flag a PI for review (body: reason)
POST /admin/{id}/review         set review_status (body: review_status)
POST /{id}/confirm              move status → requires_capture
POST /{id}/capture              move status → succeeded + ledger entry
POST /{id}/cancel               move status → canceled

7. PAYMENT SERVICE  (app/services/payment_service.py)
─────────────────────────────────────────
create_payment_intent(db, amount, currency, merchant_id, idempotency_key)
  - if idempotency_key exists → return existing record
  - id = "pi_" + count+1
  - status = requires_payment_method
  - create_event("payment_intent.created") + create_dispatches_for_event()
  - db.commit()

get_payment_intent(db, id) → raises PaymentIntentNotFoundError if missing

confirm_payment_intent(db, id)
  - guard: not canceled / succeeded / already requires_capture / review rejected
  - status → requires_capture
  - create_event("payment_intent.confirmed")

capture_payment_intent(db, id)
  - guard: must be requires_capture, not canceled/succeeded/review rejected
  - find or create cash + merchant_payable LedgerAccounts
  - status → succeeded
  - create_ledger_entry(type=payment_succeeded)
      postings: cash +amount, payable -amount
  - create_event("payment_intent.succeeded")

cancel_payment_intent(db, id)
  - guard: not succeeded, not already canceled
  - status → canceled
  - create_event("payment_intent.canceled")

flag_payment_intent(db, id, reason)
  - is_flagged=True, review_status=pending_review, review_reason=reason

review_payment_intent(db, id, review_status)
  - guard: must be flagged
  - sets review_status

9. REFUND SERVICE  (app/services/refunds_service.py)
─────────────────────────────────────────
create_refund(db, payment_intent_id, refund_amount, idempotency_key)
  - idempotency guard (same as PI)
  - validates PI exists, amount > 0, amount <= PI amount
  - status = pending
  - create_event("refund.created")

confirm_refund(refund_id, db)
  - guard: status must be pending, review not rejected
  - reverses ledger: payable +amount, cash -amount
  - create_event("refund.confirmed")

decline_refund / cancel_refund
  - guard: status must be pending
  - sets status accordingly
  - create_event("refund.declined" / "refund.canceled")

flag_refund / review_refund  same pattern as payments

─────────────────────────────────────────
11. WEBHOOK SERVICES
─────────────────────────────────────────
events.py — create_event(db, event_type, object_id, payload)
  - creates Event record, flushes, returns it

dispatch.py — create_dispatches_for_event(db, merchant_id, event)
  - queries active WebhookEndpoints for merchant
  - for each endpoint where event.type in endpoint.event_types
      creates WebhookDispatch(status=pending)

delivery.py — process_pending_dispatches(db)
  - fetches all pending WebhookDispatches
  - for each dispatch:
      builds HMAC-SHA256 signature from payload + endpoint.secret
      sends HTTP POST to endpoint.url with header X-Webhook-Signature
      creates WebhookDelivery record (success or failed)
      retries up to 3 times with 5-minute delay (next_retry_at)
      marks dispatch status success / failed

13. LEDGER SERVICE  (app/services/ledger_service.py)
─────────────────────────────────────────
create_ledger_entry(db, *, entry_type, reference_id, description, entry_metadata, postings)
  - validates: len(postings) >= 2
  - validates: sum of amounts == 0  (must balance)
  - creates LedgerEntry then one LedgerPosting per posting dict

get_account_balance(db, account_id) → int
  - SELECT COALESCE(SUM(amount), 0) FROM ledger_postings WHERE account_id = ?


─────────────────────────────────────────
KEY PATTERNS TO REMEMBER
─────────────────────────────────────────
- Dependency injection:  db = Depends(get_db)  in every route
- Service layer raises custom exceptions; routes catch them → HTTPException
- Idempotency: check for existing record by key before creating new
- Every state-changing action emits an Event → creates Dispatches → delivery via HMAC POST
- Ledger is double-entry: every entry has >= 2 postings that sum to 0
- Payment flow:  requires_payment_method → requires_capture → succeeded
- Refund flow:   pending → confirmed / declined / canceled
- Flagging flow: is_flagged=True, review_status=pending_review → approved / rejected
