================================================================================
  MERCHANTS API — BACKEND ENGINEERING STUDY NOTES
================================================================================

These notes cover every concept in this repo so you can rebuild it from scratch.

--------------------------------------------------------------------------------
1. WHAT THIS API DOES
--------------------------------------------------------------------------------
A payment-processing backend for merchants. Merchants can:
  - Create & manage payment intents (like Stripe)
  - Issue refunds against those payments
  - Register webhook endpoints to receive event notifications
  - View a double-entry ledger of all money movements
  - Generate API keys to authenticate requests
  - View risk / fraud summaries (admin only)

4. CORE BACKEND CONCEPTS
--------------------------------------------------------------------------------

REST API
  - HTTP protocol: GET (read), POST (create), PUT (replace), DELETE (remove)
  - Status codes: 200 OK, 201 Created, 400 Bad Request, 401 Unauthorized,
    403 Forbidden, 404 Not Found, 409 Conflict, 429 Too Many Requests,
    503 Service Unavailable
  - URL path params: /payment_intents/{id}
  - Query params: ?limit=20&status=succeeded
  - Request body: JSON payload sent with POST/PUT
  - Response body: JSON returned to caller

Authentication
  - Client puts their API key in the "Authorization" header
  - Server hashes it with SHA-256 and looks up the hash in the DB
  - Never store raw API keys — only store the hash
  - Admin routes use a second check: api_key.is_admin must be True

Idempotency
  - Client sends optional "Idempotency-Key" header
  - If the server sees the same key again it returns the original result
  - Prevents duplicate payments if the client retries after a network error

Pagination (cursor-based)
  - "starting_after" = ID of the last item on the previous page
  - Server fetches limit+1 rows; if count > limit, "has_more": true
  - Returns {"data": [...], "has_more": true/false}

Events & Webhooks
  - Every state change (payment confirmed, refund created, etc.) creates an
    Event row in the DB
  - The dispatch service finds all active WebhookEndpoints for that merchant
    that subscribed to that event type and creates a WebhookDispatch per endpoint
  - The delivery service makes an HTTP POST to each endpoint URL with a
    HMAC-SHA256 signature in the header so the receiver can verify authenticity
  - If delivery fails it is retried with exponential back-off

Double-Entry Ledger
  - Every monetary transaction has at least two postings (debit + credit)
  - Debits and credits for one entry must net to zero (balanced books)
  - Accounts have a type: "cash" or "merchant_payable"
  - Balance = sum of all posting amounts for an account

Risk / Fraud
  - On payment creation, a risk_score is calculated (based on velocity, amount)
  - Payments over HIGH_VALUE_PAYMENT_THRESHOLD are auto-flagged for review
  - Velocity limit: too many payments in a short window → 429 error
  - Admin can flag, approve, or reject individual payments/refunds

Observability
  - Structured logging: every request logs method, path, status, latency
  - request_id_context: each request gets a UUID attached to every log line
  - Prometheus metrics exposed at /metrics: request counts, error counts,
    latency histograms per route

6. PYDANTIC SCHEMAS
--------------------------------------------------------------------------------
Pydantic validates incoming JSON and serialises outgoing data.

from pydantic import BaseModel, Field, field_validator
from enum import Enum

class Status(str, Enum):
    pending = "pending"
    confirmed = "confirmed"

class CreateRequest(BaseModel):
    amount: int = Field(..., gt=0)          # required, must be > 0
    currency: str = Field(..., min_length=3, max_length=3)
    merchant_id: str

    @field_validator("currency")
    @classmethod
    def validate_currency(cls, v: str) -> str:
        if not v.isalpha():
            raise ValueError("must be letters only")
        return v.lower()

class Response(BaseModel):
    id: str
    amount: int
    status: Status

    model_config = {"from_attributes": True}   # allows ORM object → Pydantic

Key: "from_attributes": True lets you return a SQLAlchemy model object directly
     as the response_model — Pydantic reads its attributes automatically.

# Base class all models inherit from
from sqlalchemy.orm import declarative_base
Base = declarative_base()

# Model definition
class PaymentIntent(Base):
    __tablename__ = "payment_intents"

    id            = Column(String, primary_key=True, index=True)
    merchant_id   = Column(String, nullable=False, index=True)
    amount        = Column(Integer, nullable=False)
    currency      = Column(String(3), nullable=False)
    status        = Column(String, nullable=False)
    is_flagged    = Column(Boolean, default=False, nullable=False)
    created_at    = Column(DateTime, server_default=func.now())
    updated_at    = Column(DateTime, server_default=func.now(), onupdate=func.now())

# Foreign key
payment_intent_id = Column(String, ForeignKey("payment_intents.id"), nullable=False)

# JSONB column (PostgreSQL only, stores arbitrary JSON efficiently)
payload = Column(JSONB, nullable=False)

# Computed column (SQL subquery result attached to the model)
PaymentIntent.total_refunded = column_property(
    select(func.coalesce(func.sum(Refunds.amount), 0))
    .where(Refunds.payment_intent_id == PaymentIntent.id, Refunds.status == "confirmed")
    .scalar_subquery()
)

9. ALEMBIC MIGRATIONS
--------------------------------------------------------------------------------
Alembic version-controls your database schema changes.

alembic init alembic             # sets up alembic directory
alembic revision --autogenerate -m "add column"   # generate migration
alembic upgrade head             # apply all pending migrations
alembic downgrade -1             # roll back one migration

Each migration file has:
  - revision  — unique ID for this migration
  - down_revision — ID of the previous migration (forms a chain)
  - upgrade()  — SQL to apply the change
  - downgrade()— SQL to undo the change

op.create_table("my_table", sa.Column("id", sa.String(), primary_key=True), ...)
op.add_column("table", sa.Column("col", sa.String()))
op.drop_table("my_table")

10. AUTHENTICATION — HOW IT WORKS END-TO-END
--------------------------------------------------------------------------------
1. POST /v1/api_keys  →  server generates random key (secrets.token_hex(32))
                         hashes it (hashlib.sha256(key.encode()).hexdigest())
                         stores only the HASH in api_keys table
                         returns the RAW key to the client (only time it's shown)

2. Client stores the raw key and sends it in every request:
   Authorization: <raw_key>

3. Server dependency require_api_key():
   a. Takes Authorization header value
   b. SHA-256 hashes it
   c. Queries api_keys WHERE key_hash = ? AND is_active = True
   d. Raises 401 if not found
   e. Returns the ApiKey object (contains merchant_id, is_admin)

4. require_admin_api_key() wraps require_api_key() and additionally
   checks api_key.is_admin, raises 403 if false.

11. DATABASE MODELS (all tables)
--------------------------------------------------------------------------------

payment_intents      — core payment record
  id, merchant_id, amount, captured_amount, risk_score, currency, status,
  idempotency_key, is_flagged, review_status, review_reason, created_at, updated_at
  status values: requires_payment_method → requires_capture → succeeded | canceled

refunds              — refund against a payment intent
  id, merchant_id, payment_intent_id (FK), amount, status, idempotency_key,
  is_flagged, review_status, review_reason, created_at, updated_at
  status values: pending → confirmed | declined | canceled

events               — immutable audit log of every state change
  id, type (e.g. "payment_intent.created"), object_id, payload (JSONB), created_at

webhook_endpoints    — a merchant's registered URL to receive events
  id, merchant_id, url, event_types (JSONB list), secret, is_active, created_at, updated_at

webhook_dispatches   — one pending delivery job per (event × endpoint)
  id, event_id (FK), webhook_endpoint_id (FK), payload (JSONB), status,
  next_retry_at, created_at

webhook_deliveries   — one row per HTTP attempt for a dispatch
  id, webhook_dispatch_id (FK), attempt_number, response_status, response_body,
  error_message, status, next_retry_at, delivered_at, created_at

ledger_accounts      — a named account for a merchant (cash, merchant_payable)
  id, merchant_id, name, account_type, currency, created_at

ledger_entries       — a double-entry transaction (groups postings)
  id, entry_type, reference_id, description, entry_metadata (JSONB), created_at

ledger_postings      — one debit or credit line within a ledger entry
  id, entry_id (FK), account_id (FK), amount, currency, created_at
  (positive = debit, negative = credit; must balance per entry)

api_keys             — hashed API keys for merchant auth
  id, key_hash, merchant_id, is_active, is_admin, created_at

12. SERVICE LAYER — BUSINESS LOGIC
--------------------------------------------------------------------------------
Services contain the real logic. Routes are thin — they just validate input,
call a service function, and map exceptions to HTTP status codes.

payment_service.py
  create_payment_intent()  — idempotency check → velocity limit → risk score
                             → build PaymentIntent → create Event → dispatch webhooks
  confirm_payment_intent() — status: requires_payment_method → requires_capture
  capture_payment_intent() — status: requires_capture → succeeded (or stays)
                             creates double-entry ledger posting
  cancel_payment_intent()  — cannot cancel if already succeeded
  flag_payment_intent()    — sets is_flagged=True, review_status=pending_review
  review_payment_intent()  — sets review_status to approved|rejected

refunds_service.py
  create_refund()   — payment must be succeeded; refund ≤ remaining capturable amount
  confirm_refund()  — pending → confirmed
  decline_refund()  — pending → declined
  cancel_refund()   — pending → canceled
  flag_refund()     — sets is_flagged
  review_refund()   — sets review_status

risk_service.py
  calculate_risk_score()   — score 0-100 based on amount, recent activity
  enforce_velocity_limit() — raises RiskRateLimitError if too many payments
                             in the last time window (configurable)

ledger_service.py
  create_ledger_entry()          — creates entry + postings in a transaction
  get_account_balance_details()  — sums all postings for an account
  get_balance_sheet()            — groups accounts by type + currency for a merchant
  list_account_entries()         — paginated list of entries for an account

events.py
  create_event()  — inserts an Event row (type, object_id, JSONB payload)

dispatch.py
  create_dispatches_for_event()  — finds all active endpoints subscribed to that
                                   event type, creates a WebhookDispatch per one

delivery.py
  process_pending_dispatches()   — polls pending dispatches, sends HTTP POST to
                                   each endpoint, records delivery result,
                                   schedules retry on failure

timestamp_service.py
  get_created_at() / get_updated_at()  — generic helpers to fetch timestamp
                                         fields from any model by primary key

16. API ENDPOINTS QUICK REFERENCE
--------------------------------------------------------------------------------
All routes (except POST /v1/api_keys) require Authorization header.

PAYMENT INTENTS  prefix: /v1/payment_intents
  GET    /                           list (paginated, filterable)
  POST   /                           create (body: merchant_id, amount, currency)
  GET    /{id}                       get one
  POST   /{id}/confirm               requires_payment_method → requires_capture
  POST   /{id}/capture               requires_capture → succeeded
  POST   /{id}/cancel                cancel if not succeeded
  GET    /{id}/transactions          timeline of events for this payment
  GET    /transactions               all transactions for the merchant
  GET    /admin/flagged              [admin] flagged payments
  POST   /admin/{id}/flag            [admin] flag for review
  POST   /admin/{id}/review          [admin] approve or reject

REFUNDS  prefix: /v1/refunds
  GET    /                           list refunds
  POST   /payment_intents/{id}/refunds  create refund (body: amount)
  GET    /{refund_id}                get one
  POST   /{refund_id}/confirm        pending → confirmed
  POST   /{refund_id}/decline        pending → declined
  POST   /{refund_id}/cancel         pending → canceled
  POST   /{refund_id}/flag           flag for review
  GET    /admin/flagged              [admin] flagged refunds
  POST   /admin/{refund_id}/review   [admin] review a refund

WEBHOOKS  prefix: /v1/webhooks
  POST   /endpoints                  register a webhook URL
  GET    /endpoints                  list your endpoints
  PUT    /endpoints/{id}             update an endpoint
  DELETE /endpoints/{id}             delete an endpoint
  GET    /endpoints/{id}/deliveries  delivery history for endpoint
  GET    /dispatches                 list dispatch jobs
  GET    /dispatches/{id}            get one dispatch + deliveries
  GET    /deliveries                 list all deliveries
  POST   /dispatches/process         trigger delivery of pending dispatches

LEDGER  prefix: /v1/ledger
  POST   /accounts                   create an account
  GET    /accounts                   list your accounts
  POST   /entries                    create a ledger entry
  GET    /accounts/{id}/balance      account balance
  GET    /accounts/{id}/entries      paginated entry history
  GET    /merchant/{id}/balance_sheet grouped balance sheet

API KEYS  prefix: /v1/api_keys
  POST   /                           create a new API key (returns raw key once)

RISK  prefix: /v1/admin/risk
  GET    /summary                    [admin] fraud summary per merchant

TIMESTAMPS  prefix: /v1/timestamps/payment_intents
  GET    /{id}/created_at
  GET    /{id}/updated_at

SYSTEM
  GET    /                           health ping
  GET    /health                     db connectivity check
  GET    /metrics                    Prometheus metrics

18. TESTING
--------------------------------------------------------------------------------
Tests use pytest + httpx TestClient to simulate HTTP requests without a real server.

Run: PYTHONPATH=. pytest app/tests -q

conftest.py provides shared fixtures:
  - db fixture: in-memory SQLite session (no real Postgres needed)
  - client fixture: TestClient(app) with the test DB injected

Pattern:
  def test_create_payment(client, db):
      response = client.post("/v1/payment_intents", json={...}, headers={"Authorization": key})
      assert response.status_code == 201
      assert response.json()["status"] == "requires_payment_method"

19. HOW TO REBUILD FROM SCRATCH (checklist)
--------------------------------------------------------------------------------
 1. pip install fastapi uvicorn sqlalchemy psycopg2-binary alembic pydantic-settings httpx
 2. Create app/core/config.py  — Pydantic Settings class reading DATABASE_URL from env
 3. Create app/core/exceptions.py  — custom Exception subclasses
 4. Create app/db/database.py  — engine, SessionLocal, get_db(), Base
 5. Create app/db/models/models.py  — one class per table inheriting Base
 6. Create app/schemas/*.py  — Pydantic BaseModel for each request/response shape
 7. Create app/services/*.py  — pure business logic functions, no HTTP
 8. Create app/auth/dependencies.py  — require_api_key, require_admin_api_key
 9. Create app/api/routes/*.py  — APIRouter, routes call services, map exceptions
10. Create app/main.py  — FastAPI(), middleware, include_router(), Base.metadata.create_all()
11. alembic init alembic → edit env.py to point at your models → alembic revision --autogenerate
12. Write Dockerfile + docker-compose.yaml
13. docker compose up  →  app available at http://localhost:8000
