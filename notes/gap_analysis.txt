1. REFUNDS
------------------------------------------------------------------------
[x] Refund model (Refunds in models.py)
[x] Refund schemas (refunds_schemas.py — status enum exists)
[~] Refund service (refunds_service.py exists, but has issues — see bugs)
[~] Refund routes (refunds/routes exist, but have bugs — see bugs)
[x] Idempotency key on refund create
[x] Only allow refund on succeeded payment intent? — NOT ENFORCED
    Issue: create_refund() checks amount rules but never checks that the
    parent PaymentIntent.status == "succeeded". Any payment intent can be
    refunded, even canceled ones.
[x] Refund amount must be positive — enforced
[~] Refund amount must not exceed payment amount — enforced, but partial:
    it only checks the original payment amount, not the sum of prior refunds.
    A payment of $100 can be refunded three times for $100 each.

ROUTE BUGS IN refunds.py:
  - create_refund_route() does not pass an amount from the request body.
    The route signature has no 'amount' param, and the service call is
    create_refund(db, payment_intent_id, idempotency_key) — missing amount.
  - get_refund_route() path is "/{refund_id}/refunds" — should be
    GET /v1/refunds/{refund_id}.
  - get_refund_route() uses 'payment_intent_id' as argument but the path
    param is 'refund_id'. Same mismatch in confirm/decline/cancel routes.
  - decline_refund_route and cancel_refund_route use @router.get() instead
    of @router.post(). State-changing actions must be POST.
  - The refunds router is NOT registered in main.py. Refund routes are
    completely unreachable.

REFUND SCHEMA GAP:
  - There is no RefundRequest schema (with amount field) and no
    RefundResponse schema. Refund routes return raw ORM objects without
    a typed response_model.

TOP PRIORITY FIXES TO ROUND OFF THE PROJECT
------------------------------------------------------------------------
These are the items that would make the biggest difference:

1. Register the refunds router in main.py.
2. Fix create_refund_route to accept and pass a body with 'amount'.
3. Fix decline/cancel refund routes to use POST not GET.
4. Enforce succeeded status check before allowing refund creation.
5. Add created_at / updated_at to PaymentIntentResponse and a new
   RefundResponse schema.
6. Call create_ledger_entry() automatically inside capture_payment_intent()
   and confirm_refund() so balances actually track real activity.
7. Call create_dispatches_for_event() inside refunds_service for refund
   events so webhook delivery works end-to-end for refunds.
8. Add HMAC signature header to outgoing webhook payloads using the
   stored endpoint secret.
9. Add a LedgerAccount creation route so the ledger is usable via API.
10. Remove Base.metadata.create_all from main.py and rely solely on Alembic.
